Topic 01

HTML & Semantics

Structure, meaning, and why semantic markup matters.

01
Why use <section>, <article>, <nav>, <aside> instead of generic <div>?
Hint: Semantics — screen readers, SEO, maintainability, landmark navigation. <div> carries no meaning.
02
Hint: <strong> and <em> carry semantic emphasis — screen readers change their tone. <b> and <i> are purely visual.
03
When would you use a <table> for layout?
Hint: Never. That was a 1990s practice. Tables are for tabular data only. Modern layout uses Flexbox and Grid.
04
What does <!DOCTYPE html> do? What happens if you omit it?
Hint: Triggers standards mode. Omitting it puts the browser in quirks mode, where box model and other rules follow legacy behavior.
05
Difference between <script>, <script async>, and <script defer>?
Hint: Plain blocks parsing. async downloads in parallel and runs as soon as ready (order not guaranteed). defer downloads in parallel but runs in order after HTML parse.
06
What is the DOM? How is it built?
Hint: Tree of nodes representing the page. Built by the browser as HTML is parsed. JavaScript manipulates it to change the UI.
07
Why does <label for="x"> matter?
Hint: Accessibility — clicking the label focuses the input. Screen readers announce the association. Also improves hit targets on touch screens.
08
What is the difference between block, inline, and inline-block elements?
Hint: Block takes full width, starts on a new line. Inline flows with text, ignores width/height. Inline-block flows with text but accepts width/height.
09
Why is the HTML structure important for SEO?
Hint: Search engines parse headings, landmarks, and semantic tags to understand content hierarchy. Also affects readability for assistive tech.
Topic 02

CSS Fundamentals

Specificity, the box model, positioning, and layout systems.

01
How is specificity calculated?
Hint: Three buckets: inline styles (1000), IDs (100), classes/attributes/pseudo-classes (10), elements/pseudo-elements (1). Highest wins; ties broken by order.
02
Difference between em, rem, px, %, vw, vh?
Hint: em = parent font size. rem = root font size. px = absolute. % = parent's dimension. vw/vh = viewport percentage.
03
Box model — content-box vs border-box?
Hint: content-box (default): width excludes padding and border. border-box: width includes them. Almost every project sets * { box-sizing: border-box }.
04
Why does margin: 0 auto center a block element? When does it fail?
Hint: It distributes free horizontal space equally. Fails if the element has no explicit width, or is inline, or is absolutely positioned with both left and right set.
05
Difference between display: none, visibility: hidden, and opacity: 0?
Hint: display: none removes from layout. visibility: hidden keeps the space, hides the paint. opacity: 0 keeps the space and the element still receives clicks.
06
What is position: absolute positioned relative to?
Hint: The nearest ancestor with position other than static. If none exists, the initial containing block (viewport).
07
What is z-index and why does it sometimes not work?
Hint: Controls stacking order. Only works on positioned elements. Broken by stacking contexts — a child's z-index only competes within its parent's context.
08
Difference between Flexbox and Grid? When to use which?
Hint: Flexbox for one-dimensional layouts (row or column). Grid for two-dimensional (rows and columns). Grid for page layout, Flex for component alignment.
09
What is a CSS reset/normalize and why do people use one?
Hint: Browsers apply different default styles. A reset removes them; normalize makes them consistent. Ensures a predictable baseline across browsers.
10
Explain the difference between reflow and repaint.
Hint: Reflow recalculates layout (expensive). Repaint only redraws pixels (cheaper). Changing width causes reflow; changing color causes repaint.
Topic 03

Responsive Design

Media queries, viewport, and mobile-first thinking.

01
Difference between mobile-first and desktop-first?
Hint: Mobile-first writes base styles for small screens and adds complexity upward with min-width media queries. Desktop-first is the reverse with max-width.
02
How do media queries work? Give an example.
Hint: @media (min-width: 768px) { .nav { display: flex; } } — applies the rule only when the viewport is at least 768px wide.
03
What does <meta name="viewport" content="width=device-width"> do?
Hint: Tells mobile browsers to render at device width instead of the default ~980px zoomed-out desktop layout. Without it, responsive design breaks on phones.
04
What are common breakpoints and why those numbers?
Hint: 480 (small phone), 640 (large phone), 768 (tablet portrait), 1024 (tablet landscape / small laptop), 1280+ (desktop). Based on common device widths, not fixed rules.
05
Difference between responsive and adaptive design?
Hint: Responsive fluidly adjusts to any viewport. Adaptive jumps between fixed layouts at set breakpoints. Responsive is generally preferred.
06
How do you handle images for different screen sizes?
Hint: <picture> with srcset and sizes attributes. Serve smaller files to phones. Use modern formats (WebP, AVIF) and lazy loading.
07
What is the difference between em and rem in a media query context?
Hint: In media queries, em is relative to the browser's base font size (usually 16px), not the element's font. rem in media queries is also 16px-based. Both are more accessible than px because they scale with user settings.
Topic 04

JavaScript Fundamentals

Scope, closures, async, and the parts that trip everyone up.

01
var vs let vs const?
Hint: var is function-scoped, hoisted with undefined. let and const are block-scoped, hoisted but not initialized (temporal dead zone). const prevents reassignment.
02
What is hoisting?
Hint: Declarations are moved to the top of their scope before execution. var declarations are hoisted as undefined. Function declarations are hoisted fully. let/const are hoisted but not accessible until initialized.
03
Explain closures with an example.
Hint: A function that remembers variables from its enclosing scope even after that scope has returned. Example: a counter function that increments a variable defined outside it.
04
== vs ===?
Hint: == coerces types ('1' == 1 is true). === compares without coercion ('1' === 1 is false). Always use === unless you have a specific reason.
05
What is this and how does it change?
Hint: Depends on call site. Method call → the object. Standalone function → undefined (strict) or global (sloppy). Arrow functions → inherited from enclosing scope. new → the new instance.
06
Arrow functions — how do they differ from regular functions?
Hint: No own this (inherited lexically). No arguments object. Can't be used with new. Concise syntax.
07
map, filter, reduce — when do you use each?
Hint: map transforms each element. filter keeps matching elements. reduce accumulates into a single value. All return new arrays (except reduce).
08
What is a Promise? What is async/await?
Hint: A Promise represents a value that will exist later (resolve or reject). async/await is syntactic sugar over Promises — makes asynchronous code read like synchronous.
09
Difference between null and undefined?
Hint: undefined is the default for unassigned variables. null is an intentional "no value." Both are falsy. typeof null === 'object' is a historical bug.
10
What is event bubbling? Event delegation?
Hint: Events bubble from target up through ancestors. Delegation: attach one listener to a parent instead of many to children — catches all matching descendants.
11
Difference between addEventListener and onclick?
Hint: onclick allows only one handler. addEventListener allows multiple, supports options (capture, once, passive), and can be removed with removeEventListener.
12
What is a higher-order function?
Hint: A function that takes a function as an argument, returns a function, or both. map, filter, reduce are all higher-order.
13
What is the event loop?
Hint: JavaScript is single-threaded. The event loop pulls tasks from a queue and runs them when the call stack is empty. Microtasks (Promises) run before macrotasks (setTimeout).
Topic 05

DOM Manipulation

Selecting, updating, and event handling.

01
innerHTML vs textContent vs createElement — trade-offs?
Hint: innerHTML parses HTML — fast to write but an XSS risk. textContent is safe but no markup. createElement + appendChild is verbose but safest.
02
What is event delegation and why use it?
Hint: Attach one listener to a parent for many children. Fewer listeners, works for dynamically added elements. Use event.target.closest() to find the actual target.
03
How do you prevent default form submission?
Hint: event.preventDefault() inside the submit handler. Otherwise the browser reloads the page.
04
querySelector vs querySelectorAll?
Hint: querySelector returns the first match or null. querySelectorAll returns a static NodeList (not — unlike getElementsByClassName).
05
When would you use dataset?
Hint: Reading/writing data-* attributes. el.dataset.userId maps to data-user-id. Useful for storing state on DOM nodes.
06
How do you add/remove classes dynamically?
Hint: el.classList.add('x'), .remove('x'), .toggle('x'), .contains('x'). Cleaner than manipulating className strings.
07
What's the difference between a live and a static NodeList?
Hint: Live updates automatically when the DOM changes (e.g. getElementsByClassName). Static is a snapshot (querySelectorAll). Live lists cause surprising bugs.
Topic 06

CSS Architecture

Methodologies, tokens, and organizing styles at scale.

01
What is BEM? Why use it?
Hint: Block-Element-Modifier naming: .card__title--large. Reduces naming collisions, makes the HTML self-documenting, avoids specificity wars.
02
What are CSS custom properties? How do they differ from Sass variables?
Hint: Custom properties (--x) are live — they change at runtime and cascade. Sass variables are compile-time constants that disappear in the output.
03
Utility-first CSS (Tailwind) vs component CSS — trade-offs?
Hint: Utility-first: fast iteration, no naming, small learning curve once you know the classes, but HTML gets noisy. Component CSS: cleaner markup, but naming fatigue and dead-code risk.
04
How do you organize CSS in a large project?
Hint: Layers or ITCSS: tokens → base → layout → components → utilities. Or feature folders. The key is a predictable structure, not a specific one.
05
What problems does a preprocessor (Sass/Less) solve?
Hint: Nesting (with caution), variables, mixins, functions, partials. Modern CSS covers most of this now with custom properties and nesting.
06
What is the cascade, and how does it interact with specificity?
Hint: The cascade resolves conflicts in order: source order, specificity, importance (!important). Origin and inheritance also matter. Specificity is one input into the cascade, not the whole story.
Topic 07

Accessibility

Making the web usable by everyone.

01
What is WCAG? Name some guidelines.
Hint: Web Content Accessibility Guidelines. Four principles: Perceivable, Operable, Understandable, Robust (POUR). Three levels: A, AA, AAA.
02
What's the minimum contrast ratio for text?
Hint: WCAG AA: 4.5:1 for normal text, 3:1 for large text (18pt+ or 14pt bold). AAA is 7:1.
03
How do screen readers interact with a page?
Hint: They parse the accessibility tree, announce landmarks, headings, and interactive elements. Semantic HTML builds this tree automatically. ARIA can override or add to it.
04
What is ARIA? When do you use aria-label, role?
Hint: Accessible Rich Internet Applications — attributes that describe elements for assistive tech. First rule of ARIA: don't use ARIA if a native element does the job. aria-label labels icon-only buttons; role describes a custom widget.
05
Can you build an accessible modal? What do you need?
Hint: role="dialog" + aria-modal="true". Focus trap inside. Focus the first interactive element on open. Return focus on close. Escape closes. Backdrop click closes. Underlying content aria-hidden.
06
Why is color alone a bad way to convey information?
Hint: Color-blind users miss it. Add text, icons, or patterns. Example: red error text should also say "Error:" or show an icon.
07
What is keyboard navigation and why does it matter?
Hint: Users should reach every interactive element with Tab, activate with Enter/Space, escape modals with Escape. Don't remove focus outlines — restyle them instead.
Topic 08

Performance

Loading, rendering, and the metrics that matter.

01
What causes slow page loads?
Hint: Large JS bundles, blocking resources, unoptimized images, too many network requests, slow server response, no caching, render-blocking CSS.
02
What are Core Web Vitals?
Hint: LCP (Largest Contentful Paint), INP (Interaction to Next Paint), CLS (Cumulative Layout Shift). Google uses them as ranking signals.
03
What's the critical rendering path?
Hint: The sequence from receiving HTML to rendering pixels: parse HTML → build DOM → fetch CSS → build CSSOM → combine into render tree → layout → paint. Minimizing blocking steps speeds up first paint.
04
Why is CSS blocking but <script defer> isn't?
Hint: CSS blocks rendering because unstyled content would flash. Deferred scripts run after HTML parse, so they don't block the initial paint.
05
How do you optimize images?
Hint: Modern formats (WebP, AVIF). Correct dimensions — never downscale in CSS. srcset and sizes for responsive. loading="lazy" for below-the-fold. Compress aggressively.
06
What is lazy loading?
Hint: Deferring loading of resources until they're needed. Native: loading="lazy" on images/iframes. JS: IntersectionObserver for dynamic imports.
07
Difference between reflow and repaint?
Hint: Reflow recalculates layout (expensive). Repaint redraws pixels (cheaper). Animating properties like transform and opacity avoids reflow — that's why they're the recommended animation properties.
08
When would you use requestAnimationFrame?
Hint: For smooth animations synced with the browser's paint cycle. Preferred over setTimeout for anything visual — it stops when the tab is backgrounded and runs at the monitor's refresh rate.
09
What is a CDN and why use one?
Hint: Content Delivery Network — geographically distributed servers that cache your assets near users. Reduces latency and offloads origin traffic.
Topic 09

Security (frontend-side)

What the browser can and cannot protect you from.

01
What is XSS? How do you prevent it?
Hint: Cross-Site Scripting — attacker injects executable code via user input. Prevent by escaping output, using textContent instead of innerHTML, sanitizing with libraries, and setting Content Security Policy.
02
What is CSRF? Does frontend alone prevent it?
Hint: Cross-Site Request Forgery — a malicious site triggers actions on your site using the user's cookies. Frontend alone cannot prevent it. Needs server-side tokens (CSRF tokens) or SameSite cookie attributes.
03
Why is eval() dangerous?
Hint: Executes arbitrary strings as code. If any of it comes from user input, it's an XSS hole. Slower than compiled code. Almost never needed.
04
What is Content Security Policy?
Hint: An HTTP header (or meta tag) that whitelists which sources can load scripts, styles, images. Blocks inline scripts by default. Defense-in-depth against XSS.
05
Why should you never trust user input?
Hint: Input can come from anywhere — forms, URLs, headers, cookies. It can contain scripts, SQL, or malformed data. Always validate and escape on both client and server.
06
Difference between authentication and authorization?
Hint: Authentication = who you are (login). Authorization = what you can do (permissions). Both must be enforced server-side; the frontend can only hide UI, not prevent access.
Topic 10

Browser Behavior

What actually happens when someone visits a page.

01
What happens between typing a URL and seeing the page?
Hint: DNS lookup → TCP handshake → TLS handshake → HTTP request → server response → HTML parsing → subresource fetches → CSSOM + DOM → render tree → layout → paint → composite.
02
What is the same-origin policy?
Hint: A browser security rule — scripts on one origin cannot read data from another origin unless explicitly allowed. Origin = protocol + host + port.
03
What is CORS? Why does it exist?
Hint: Cross-Origin Resource Sharing — a controlled way to relax same-origin policy. The server sends Access-Control-Allow-Origin headers. Preflight requests (OPTIONS) handle non-simple ones.
04
Cookies vs localStorage vs sessionStorage?
Hint: Cookies: sent with every HTTP request, size limit ~4KB, can be HttpOnly/Secure. localStorage: persists forever, no expiry, ~5–10MB. sessionStorage: clears when tab closes, same size limit.
05
What is HTTP caching?
Hint: Browsers store responses. Controlled by headers: Cache-Control, ETag, Last-Modified. Avoids re-downloading unchanged assets.
06
Difference between HTTP/1.1, HTTP/2, HTTP/3?
Hint: 1.1: one request per connection (with some reuse). 2: multiplexing over one TCP connection, header compression. 3: uses QUIC (UDP) for lower latency.
Topic 11

Tooling & Workflow

The build tools and process around the code.

01
What is npm? What is package.json?
Hint: Node Package Manager — installs and manages JS dependencies. package.json lists dependencies, scripts, and project metadata.
02
What's a bundler? Why use one (Webpack, Vite, Rollup)?
Hint: Combines many files into a few bundles. Enables tree-shaking, minification, code splitting, and transpilation. Reduces HTTP requests and ships smaller code.
03
What is a build step? What does transpiling mean (Babel)?
Hint: A build step transforms source files before serving. Transpiling converts newer syntax (ES2020+) to older syntax for compatibility.
04
What is Git? Explain commit, branch, merge.
Hint: Distributed version control. commit = snapshot. branch = independent line of work. merge = combine branches back together.
05
Difference between git pull and git fetch?
Hint: fetch downloads changes but doesn't merge. pull fetches and merges in one step.
06
What is a linter? What is a formatter?
Hint: Linter (ESLint) catches bugs and style issues. Formatter (Prettier) reformats code to a canonical style. They solve different problems.
Topic 12

Frameworks & Concepts

If the course covers React/Vue/Angular, expect these.

01
Why use a framework? When not to?
Hint: Use when the app is complex, has lots of state, or teams need structure. Skip for small static sites, marketing pages, or simple forms — the overhead isn't worth it.
02
What is reactivity?
Hint: When data changes, the UI updates automatically. Frameworks achieve this via proxies (Vue 3), signals, or explicit state setters (React's setState).
03
What is the virtual DOM?
Hint: An in-memory tree of the UI. On state change, the framework diffs new vs old and applies only the necessary real DOM updates. React's approach.
04
What is a component? What is props vs state?
Hint: A component is a reusable UI unit. Props are inputs from the parent (read-only). State is internal data the component manages and can change.
05
What is unidirectional data flow?
Hint: Data flows down through props, events flow up through callbacks. Makes state predictable and debugging easier.
06
What is SSR vs CSR vs SSG?
Hint: SSR: server renders HTML per request. CSR: browser renders after JS loads. SSG: HTML built at deploy time. Each trades off speed, freshness, and complexity.
Topic 13

Design & UX

The parts that aren't code but determine whether the code works.

01
What are the principles of good visual hierarchy?
Hint: Size, contrast, spacing, position. The eye should land on the most important element first, then flow naturally through the rest.
02
Why is whitespace important?
Hint: Improves readability, groups related content, reduces cognitive load. Cramped layouts feel stressful; generous ones feel premium and calm.
03
What's the difference between UX and UI?
Hint: UX is the whole experience — flow, logic, whether users can accomplish their goal. UI is the visual layer — color, typography, spacing. UX without UI looks bad; UI without UX is a pretty trap.
04
Give an example of a bad UX pattern and how to fix it.
Hint: Example: a destructive "Delete" button right next to "Cancel" with no confirmation. Fix: move it away, use a confirm dialog, or add a short undo window.
05
What is progressive enhancement?
Hint: Build a working baseline, then layer on enhancements for capable browsers. A form that works without JS, then gets client-side validation. Opposed to graceful degradation.
06
What is graceful degradation?
Hint: Build for the modern browser, then make it not break completely on older ones. Simpler but less reliable than progressive enhancement.
Topic 14

Process & Reasoning

Questions about how you think, not just what you know.

01
Why did you choose this stack?
Hint: Have an actual reason tied to the project scope. "I chose X because Y, and I accepted the trade-off that Z." Don't say "it's popular."
02
What alternatives did you consider?
Hint: Show you evaluated, not just picked. Even a short "I considered X but chose Y because of Z" is worth more than a confident wrong answer.
03
What would you change if you started over?
Hint: Have one or two specific answers. Vague "I'd use a framework" is weak. "I'd use real ES modules instead of a global namespace" is specific and shows you learned.
04
What was the hardest bug you fixed?
Hint: Tell a story: symptom → wrong hypotheses → how you found it → what you learned. Don't just say "there was a syntax error."
05
What did you learn that you didn't know before?
Hint: Something specific — a browser behavior, a debugging technique, a trade-off you only understood after hitting it.
06
If you had two more weeks, what would you add?
Hint: Name a real feature or improvement with a reason. Tests, real auth, better error handling, refactor of the render pipeline.
07
How would this scale to 10× the users/data?
Hint: Name bottlenecks and fixes. Server-side pagination, caching, debouncing input, virtual lists, moving auth to the server. Vague "I'd use a bigger server" is weak.
Topic 15

Defense Strategy

How to handle the room, not just the questions.

The three categories of questions. Teachers test three things: what you know, how you reason, and how you handle pressure. Different questions probe different ones.
The three buckets

Category A — Fundamentals

Definitions and facts. Specificity, box model, event bubbling, async/await. You either know them or you don't. Prepare by reviewing a standard reference.

Category B — Trade-offs

"Why did you use X instead of Y?" They're checking that you chose deliberately. Best answer names the trade-off: "I used X because of Z, but I gave up Y, which would matter if…"

Category C — Reasoning

A scenario you haven't seen. They want to hear your process. Talk out loud: what you'd try first, how you'd debug, how you'd know it worked.

Five rules for the room
01
Answer the question asked — don't ramble.
Two sentences is often enough. If they want more, they'll ask a follow-up. Long answers invite more questions.
02
Name the trade-off.
"This works, but the cost is X." Shows maturity. Teachers reward candidates who see both sides.
03
Admit what you don't know.
"I'm not sure, but I'd approach it by…" is far better than bluffing. Teachers spot bluffing instantly and it costs you more than a blank.
04
Point to evidence.
"You can see this in the DevTools Network tab." Concrete beats abstract. Offer to open the browser and demonstrate.
05
Don't get defensive.
Questions are probes, not attacks. "That's a good point — the current version doesn't handle that. Here's what I'd do…" wins every time.
The question to always be ready for
"Walk me through what happens when…" Every teacher has a version of this. Pick the most important interaction in your project and be able to trace it end-to-end: what the user does, what code runs, what the browser does, what comes back. Being able to trace one thing completely is more convincing than being able to talk vaguely about ten.
Preparation checklist
✓
Re-read the core concept list (HTML, CSS, JS) the night before.
✓
Have a one-sentence answer ready for each "why did you choose X" question.
✓
Prepare one full end-to-end walkthrough — practice out loud, three times.
✓
Have DevTools open on the console tab during the presentation.
✓
Keep the three or four most relevant source files open in editor tabs.
What NOT to do. Don't say "I'll just look it up" if you blank. Instead: "I'd start by checking whether the data is reaching the render function — I'd log it in the console." Shows process, buys time. Teachers respect that over freezing.
